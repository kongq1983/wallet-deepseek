# 后端日志与可观测性规范

## 1. 适用范围与目标
- 适用于 `backend/` 下所有后端模块、定时任务、异步处理与第三方集成调用链路。
- 目标是保证日志可检索、链路可还原、异常可定位、问题可追溯。
- 本规范为后端全域基线，钱包链路可作为首个验收样板，不限定于单一业务域。

## 2. 日志级别与事件分类
- 日志级别应与事件严重度匹配：调试信息、业务过程、可预期失败、系统故障应清晰分层。
- 业务可预期失败应可区分于系统不可预期故障，避免告警噪音与误判。
- 同一类事件在不同模块应使用一致级别口径，禁止同义事件跨模块等级漂移。

## 3. 统一字段基线
- 所有关键日志必须具备统一字段基线，至少包含：`traceId`、`bizKey`、`module`、`operator`。
- 涉及失败或异常的日志应补充可检索的错误语义字段（如错误码、失败阶段、失败类型）。
- 字段命名应全局一致，禁止同一语义使用多套键名。

## 4. 关键埋点位置
- 请求入口必须记录基础上下文，确保链路起点可定位。
- 关键状态跃迁必须记录前后状态与业务主键，确保流程演进可追踪。
- 外部系统调用必须记录请求意图、结果摘要与失败原因分类。
- 补偿动作与终态收敛必须留痕，确保故障闭环可审计。

## 5. 脱敏与留存要求
- 日志必须遵守最小暴露原则，禁止输出明文凭据、密钥、令牌与其他敏感信息。
- 脱敏规则需保持一致，避免同一字段在不同模块出现明暗文不一致。
- 日志留存、归档与清理应有统一口径，满足运维排障与审计合规需要。
- 后端日志必须采用统一结构化日志组件；具体调用口径与禁止项由后续补充条款明确。

## 6. 评审检查清单
- [ ] 是否覆盖入口、状态跃迁、外部调用、补偿与终态等关键节点。
- [ ] 是否满足统一字段基线且命名一致。
- [ ] 是否正确区分业务失败与系统故障并使用一致级别。
- [ ] 是否完成敏感信息脱敏与留存策略检查。
- [ ] 是否使用统一结构化日志组件输出日志。
