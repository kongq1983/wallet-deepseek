# 后端代码风格规范

## 1. 适用范围
- 适用于 `backend/` 下所有 Java 代码。

## 2. 命名规范
- 包名与目录名使用小写英文语义词，禁止拼音缩写与无语义缩写。
- 类名使用名词，方法名使用动词短语。
- 布尔值命名使用可判断语义，如 `isLocked`、`hasPermission`。
- 常量名必须表达业务语义，禁止 `TEMP`、`DATA1`、`VALUE_X`。

## 3. 枚举规范
- 枚举类必须提供 `label` 字段，用中文解释枚举值的业务含义。
- `label` 仅用于展示、日志、审计或错误提示等语义说明场景，业务判断必须使用枚举值本身，禁止依赖 `label` 做逻辑分支。

## 4. 方法与职责
- 单个方法只负责一个业务动作。
- 方法参数超过 7 个时必须优先封装对象。
- 返回值语义必须稳定，禁止依赖隐式副作用传递关键结果。
- 对外方法命名必须体现业务语义，禁止滥用 `doXxx`、`handleXxx`。

## 5. 分层风格
- Controller 只做协议转换与参数校验。
- 业务编排放在 `cmdservice`/`qryservice`，领域规则放在 `domain`。
- Mapper/Repository 命名必须体现聚合边界，禁止跨聚合读写。

## 6. 异常与日志
- 业务异常必须使用 `BusinessException`。
- 禁止吞异常，日志必须包含可定位上下文。
- 对外错误信息必须可读且不泄露内部实现细节。

## 7. 注释规范
- 所有类名、属性名、方法名必须补充中文注释（建议使用 Javadoc），明确业务语义与使用边界。
- 注释只解释“为什么”，不复述“代码做什么”。
- 代码变更后必须同步更新注释，禁止保留失效注释。

## 8. 评审检查点
- 命名是否准确表达业务语义。
- 枚举类是否提供中文 `label`，且业务逻辑未依赖 `label` 判断。
- 类、属性、方法是否均包含中文注释且与实现保持一致。
- 是否存在跨层调用或职责越界。
- 异常是否可追踪且可定位。
- 是否引入重复实现或不必要复杂度。
