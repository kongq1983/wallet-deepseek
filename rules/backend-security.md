# 后端安全规范

## 1. 适用范围
- 适用于 `backend/` 下所有 Java 代码与后端集成配置。
- 本规范聚焦认证授权、数据保护、接口安全与安全评审基线。

## 2. 认证与授权基线
- 所有受保护接口必须经过统一鉴权链路，禁止在业务代码中绕过鉴权。
- 权限判断应基于明确的角色/权限模型，禁止仅依赖前端可见性控制。
- 鉴权失败应返回统一错误语义，避免暴露内部权限策略细节。

## 3. 输入校验与输出约束
- 外部输入必须做类型、长度、格式与业务边界校验。
- 禁止拼接 SQL、脚本或命令字符串，统一使用参数化与安全 API。
- 对外输出不得回传内部堆栈、SQL 片段、凭据与框架内部实现细节。

## 4. 敏感数据与日志脱敏
- 敏感字段（密码、令牌、密钥、身份证件、手机号等）禁止明文落日志。
- 异常日志需保留定位所需上下文，但必须进行必要脱敏。
- 持久化前应明确敏感字段存储策略（加密、哈希或最小化存储）。

## 5. 密钥与凭据管理
- 所有密钥与凭据仅通过环境变量或密钥托管系统注入，禁止入库入仓。
- 密钥使用应具备轮换能力，禁止硬编码长期静态密钥。
- 不同环境必须隔离凭据，禁止测试凭据流入生产。

## 6. 第三方接口与回调安全
- 第三方调用必须设置超时、重试边界与失败降级策略。
- 回调接口必须验证来源真实性（签名、时间窗、重放保护等）。
- 对外部返回数据按不可信输入处理，先校验再入域。

## 7. 安全评审检查清单
- [ ] 新增接口是否完成鉴权、授权与输入校验。
- [ ] 敏感数据是否已脱敏，日志是否可审计且不泄密。
- [ ] 密钥注入与轮换策略是否满足环境隔离要求。
- [ ] 第三方调用与回调是否具备防篡改、防重放与失败兜底机制。
