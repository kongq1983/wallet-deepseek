# 后端租户上下文规范

## 1. 适用范围

- 适用于 `backend/` 下所有涉及租户归属、认证上下文、领域事件、定时任务、异步流程、数据库访问与审计记录的后端代码。
- 本规范对应架构决策记录：`@docs/adr/0002-single-tenant-runtime-multi-tenant-ready.md`。
- 当前阶段系统采用“单租户运行、多租户就绪”策略：不实现完整多租户能力，但所有租户归属型业务链路必须显式携带并校验租户上下文。

## 2. 核心原则

- **默认业务租户固定为 `1L`**：`1L` 是当前部署的默认业务租户。
- **`0L` 不是业务租户**：`tenantId == null` 或 `tenantId <= 0` 均为非法。
- **租户 ID 来自执行上下文**：禁止业务代码自行猜测、硬编码或从不可信输入接收租户 ID。
- **显式传递优先**：租户隔离主路径必须通过方法参数显式传递 `tenantId`，不得依赖 `ThreadLocal`、MDC 或隐式 SQL 拦截器。
- **HTTP 不暴露租户入参**：前端和外部调用方不得通过 HTTP JSON 入参指定 `tenantId`。
- **数据库不兜底默认租户**：新增表的 `tenant_id` 必须 `NOT NULL`，不得设置 `DEFAULT 1` 或其他默认租户值。

## 3. 租户公共能力

- 租户公共能力统一放在 `common.tenant` 包下。
- 该包至少应包含：
  - 默认租户常量，例如 `TenantConstants.DEFAULT_TENANT_ID = 1L`。
  - 租户合法性校验，例如 `TenantIds.requireValid(Long tenantId)`。
  - 当前租户解析能力，例如从登录态读取当前用户归属租户。
- 禁止在业务限界上下文、聚合、仓储或监听器中重复定义 `DEFAULT_TENANT_ID`。
- 当前不引入 `TenantId` 值对象，统一使用 `Long tenantId`。

## 4. 入口上下文规则

### 4.1 HTTP 用户端接口

- 用户端接口必须从登录态解析当前用户归属租户。
- 请求体中的 `Cmd`/`Qry` 不得包含 `tenantId`。
- Controller 调用应用服务时，应以显式参数传入租户：

```java
cmdService.create(tenantId, cmd);
qryService.query(tenantId, qry);
```

### 4.2 HTTP 管理端接口

- 当前系统只有租户管理员，没有平台管理员。
- 管理端接口同样必须从管理员登录态解析归属租户。
- 禁止“管理员没有租户时自动使用默认租户”的隐式逻辑。

### 4.3 领域事件监听器

- 监听器必须从领域事件载荷读取 `tenantId`。
- 监听器不得自行读取默认租户常量来替代事件租户。
- 监听器构造后续 Command/Query 后，必须以显式参数传入应用服务。

### 4.4 定时任务

- 定时任务必须从任务上下文、任务记录或明确的租户枚举策略解析租户。
- 当前单租户任务可以显式使用默认业务租户 `1L`，但该逻辑必须位于任务上下文生成处，不得散落到业务服务内部。

### 4.5 异步流程

- 异步流程必须从消息、事件、任务记录，或提交异步任务时捕获的上下文中解析租户。
- 禁止依赖 `ThreadLocal` 在线程切换后继续保留租户上下文。

## 5. 应用服务边界

- `CmdService`/`QryService` 方法必须显式接收 `tenantId`，而不是从 `Cmd`/`Qry` 中读取。
- 应用服务入口第一步必须校验 `tenantId` 合法。
- `Cmd`/`Qry` 作为 HTTP 请求体模型时，不得增加 `tenantId` 字段。
- 应用服务向领域模型、仓储、Mapper、外部适配器传递租户时，必须使用已校验的 `tenantId`。

## 6. 登录态与账号归属

- 登录成功时，登录态必须保存用户归属租户 ID。
- 登录逻辑必须从用户记录读取 `tenantId`，不得硬编码默认租户。
- 当前单租户阶段，新建或同步用户默认归属 `1L`。
- 用户记录缺少合法租户时，登录应失败或阻断并等待数据修复，不得自动兜底默认租户。
- 当前账号只属于一个租户，不支持账号跨租户归属或租户切换。

## 7. 领域模型与领域事件

- 租户归属型聚合根必须持有 `tenantId`。
- 创建租户归属型聚合时必须传入已校验的 `tenantId`。
- 从数据库恢复聚合时必须恢复 `tenantId`。
- 聚合发出领域事件时必须使用自身 `tenantId`。
- 领域对象内部不得定义默认租户常量。
- 领域事件构造器必须继续遵守领域事件规范，调用 `super(tenantId)`。
- 全局字典、全局枚举、系统模板等非租户归属对象可以不携带 `tenantId`，但必须明确其全局属性。

## 8. 持久化与数据库访问

- 本阶段不启用 MyBatis-Plus 租户拦截器。
- Repository/Mapper 方法签名必须显式接收 `tenantId`。
- Mapper XML 中的查询、更新、删除语句必须显式包含 `tenant_id = #{tenantId}` 条件。
- 新增租户归属业务表必须包含 `tenant_id BIGINT NOT NULL`。
- 新增租户归属业务表不得为 `tenant_id` 设置数据库默认值。
- 应用层插入数据时必须显式写入 `tenant_id`。
- 租户内唯一业务键必须将 `tenant_id` 纳入唯一约束。
- 高频租户内查询索引应优先以 `tenant_id` 作为前导列。
- 关联两个租户归属实体时，应优先通过 `(tenant_id, biz_id)` 组合引用，避免跨租户关联。

## 9. 表分类规则

- 默认所有业务数据表都是租户归属表，必须包含 `tenant_id`。
- 只有明确列入全局表白名单的表可以没有 `tenant_id`。
- 领域事件表、消费记录表、业务任务表和租户内审计表必须包含 `tenant_id`。
- 当前不建立 `tenant` 表，也不通过外键引用租户。

## 10. 禁止行为

- 禁止将 `tenantId` 暴露为普通 HTTP JSON 入参。
- 禁止在现有 `Cmd`/`Qry` 中增加租户上下文字段。
- 禁止在业务服务、聚合、仓储、监听器中散落硬编码 `0L`、`1L` 作为租户。
- 禁止使用 `0L` 表示默认业务租户。
- 禁止依赖数据库 `DEFAULT` 自动填充租户。
- 禁止依赖 `ThreadLocal` 作为租户隔离主路径。
- 禁止依赖 MyBatis-Plus 租户拦截器替代显式租户条件。
- 禁止跨租户查询、更新、删除时省略明确的租户边界；平台级跨租户能力当前不在系统范围内。

## 11. 自检清单

- [ ] 当前入口是否能明确说明 `tenantId` 来源。
- [ ] HTTP 请求体是否未暴露 `tenantId`。
- [ ] `CmdService`/`QryService` 是否显式接收并校验 `tenantId`。
- [ ] 租户归属型聚合是否持有并使用自身 `tenantId` 发布事件。
- [ ] Repository/Mapper 方法是否显式接收 `tenantId`。
- [ ] Mapper XML 的查询、更新、删除是否包含 `tenant_id` 条件。
- [ ] 新增表是否避免为 `tenant_id` 设置数据库默认值。
- [ ] 唯一约束和高频索引是否纳入 `tenant_id`。
- [ ] 是否没有新增模块级 `DEFAULT_TENANT_ID`。
- [ ] 是否没有把 `0L` 写成业务租户。
