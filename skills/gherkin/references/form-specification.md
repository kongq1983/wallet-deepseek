# 表单场景规范

_当场景涉及表单新增、编辑、数据录入时，必须阅读本文件并遵循以下规范。_

---

## 1. 触发条件

当用户要求编写的场景涉及以下行为时，本规范自动生效：

- 新增/创建实体（如"创建活动""新增接入方""创建申请单"）
- 编辑/更新实体（如"修改活动信息""更新接入方配置"）
- 任何需要用户填写多个字段并提交的操作

---

## 2. 表单字段规格表（必须）

在 `.feature` 文件的 `功能` 描述之后、第一个 `场景` 之前，**必须**以注释块形式定义表单字段规格表。格式如下：

```gherkin
# 表单字段规格：
# | 字段名   | 控件类型   | 必填 | 约束                         |
# | 活动名称 | 文本输入   | 是   | 最大 50 字符；不可重复       |
# | 开始时间 | 日期选择器 | 是   | 格式 YYYY-MM-DD              |
# | 结束时间 | 日期选择器 | 是   | 格式 YYYY-MM-DD；须晚于开始时间 |
# | 活动类型 | 下拉选择   | 是   | 可选值：积分/优惠券/实物     |
# | 备注     | 多行文本   | 否   | 最大 200 字符                |
```

### 2.1 列定义

| 列名     | 说明                                                                 |
| -------- | -------------------------------------------------------------------- |
| 字段名   | 业务可读的字段名称，与 UI 标签一致                                   |
| 控件类型 | 前端交互控件类型（见下方标准控件类型表）                             |
| 必填     | `是` 或 `否`                                                         |
| 约束     | 校验规则，多条用中文分号 `；` 分隔。无约束时填 `—`                   |

### 2.2 标准控件类型

| 控件类型       | 适用场景                         | 约束中应注明                     |
| -------------- | -------------------------------- | -------------------------------- |
| 文本输入       | 短文本（名称、标题等）           | 最大字符数                       |
| 多行文本       | 长文本（描述、备注等）           | 最大字符数                       |
| 数字输入       | 整数或小数（金额、数量等）       | 最小值；最大值；小数位数         |
| 下拉选择       | 单选枚举（状态、类型等）         | 可选值列表                       |
| 多选           | 多选枚举（标签、权限等）         | 可选值列表；最多可选数           |
| 单选           | 互斥选项（性别、是否等）         | 可选值列表                       |
| 日期选择器     | 日期（开始/结束日期等）          | 格式（如 YYYY-MM-DD）            |
| 时间选择器     | 时刻（开始/结束时间等）          | 格式（如 HH:mm）                 |
| 日期时间选择器 | 日期+时刻                        | 格式（如 YYYY-MM-DD HH:mm）      |
| 开关           | 布尔切换（启用/禁用等）          | 默认值                           |
| 文件上传       | 附件（图片、文档等）             | 允许格式；最大文件大小；最大数量 |
| 级联选择       | 层级数据（省市区、组织架构等）   | 层级数；数据源                   |
| 树选择         | 树形结构（分类、部门等）         | 可选层级；是否多选               |
| 自动补全       | 远程搜索匹配（用户、项目等）     | 数据源；最少输入字符数           |

### 2.3 约束书写规范

约束使用自然语言，多条之间用中文分号 `；` 分隔。常见约束模式：

| 约束类型   | 书写示例                                       |
| ---------- | ---------------------------------------------- |
| 长度限制   | `最大 50 字符`                                 |
| 格式要求   | `格式 YYYY-MM-DD`                              |
| 数值范围   | `最小 1；最大 99999`                           |
| 唯一性     | `不可重复` 或 `全局唯一`                       |
| 枚举可选值 | `可选值：积分/优惠券/实物`                     |
| 比较关系   | `须晚于开始时间` 或 `须大于 0`                 |
| 默认值     | `默认值：启用`                                 |
| 依赖关系   | `当活动类型=实物时必填`                        |

## 3. 表单填写步骤写法

### 3.1 标准填写步骤

使用数据表传递表单字段值，步骤格式统一为：

```gherkin
当 运营人员填写创建活动表单：
  | 字段名   | 值             |
  | 活动名称 | 双十一积分狂欢 |
  | 开始时间 | 2026-11-01     |
  | 结束时间 | 2026-11-11     |
而且 提交表单
```

**规则：**
- 数据表第一列固定为 `字段名`，第二列固定为 `值`
- 字段名必须与表单字段规格表中的名称完全一致
- 空值用空白表示（不填任何内容），代表用户未输入
- 提交动作单独一行（`而且 提交表单`），不合并到填写步骤中

### 3.2 部分填写（编辑场景）

编辑场景只需列出被修改的字段：

```gherkin
当 运营人员修改活动信息：
  | 字段名   | 值                 |
  | 活动名称 | 双十一积分狂欢Plus |
而且 提交表单
```

### 3.3 含下拉/多选字段的填写

下拉选择和多选字段的值直接写选项文本，多选用 `/` 分隔：

```gherkin
当 管理员填写接入方表单：
  | 字段名     | 值             |
  | 接入方名称 | 教务系统       |
  | 接入能力   | OpenAPI/OAuth2 |
  | 状态       | 启用           |
而且 提交表单
```

## 4. 校验场景覆盖规则

对于表单新增/编辑功能，**必须**覆盖以下校验场景（按优先级排序）：

### 4.1 必填校验（每个必填字段一个场景）

```gherkin
场景: 活动名称为空时提交失败
  当 运营人员填写创建活动表单：
    | 字段名   | 值         |
    | 活动名称 |            |
    | 开始时间 | 2026-11-01 |
    | 结束时间 | 2026-11-11 |
  而且 提交表单
  那么 活动名称字段应提示"请输入活动名称"
```

**提示语规范：**
- 文本输入/多行文本：`请输入{字段名}`
- 下拉选择/日期选择器/级联选择：`请选择{字段名}`
- 文件上传：`请上传{字段名}`
- 开关/单选：通常不需要必填提示（有默认值）

### 4.2 格式/范围校验（使用场景大纲）

当多个字段有类似的格式或范围约束时，使用场景大纲合并：

```gherkin
场景大纲: 字段格式不合法时提交失败
  当 运营人员填写创建活动表单：
    | 字段名   | 值       |
    | 活动名称 | 合法名称 |
    | <字段>   | <非法值> |
  而且 提交表单
  那么 <字段>字段应提示"<提示语>"

  例子:
    | 字段     | 非法值     | 提示语                  |
    | 开始时间 | 2026/11/01 | 日期格式应为 YYYY-MM-DD |
    | 结束时间 | abc        | 日期格式应为 YYYY-MM-DD |
```

### 4.3 业务规则校验（跨字段）

跨字段的业务约束单独成场景，场景名应体现规则含义：

```gherkin
场景: 活动开始时间晚于结束时间时创建失败
  当 运营人员填写创建活动表单：
    | 字段名   | 值           |
    | 活动名称 | 时间异常活动 |
    | 开始时间 | 2026-12-31   |
    | 结束时间 | 2026-12-01   |
  而且 提交表单
  那么 应提示"活动开始时间必须早于结束时间"
```

### 4.4 唯一性校验

```gherkin
场景: 活动名称重复时创建失败
  假设 已存在名称为"双十一积分狂欢"的活动
  当 运营人员填写创建活动表单：
    | 字段名   | 值             |
    | 活动名称 | 双十一积分狂欢 |
    | 开始时间 | 2026-12-01     |
    | 结束时间 | 2026-12-12     |
  而且 提交表单
  那么 应提示"活动名称已存在"
```

## 5. 提示语统一规范

| 校验类型   | 提示语模板                           | 示例                         |
| ---------- | ------------------------------------ | ---------------------------- |
| 必填-输入  | `请输入{字段名}`                     | 请输入活动名称               |
| 必填-选择  | `请选择{字段名}`                     | 请选择开始日期               |
| 必填-上传  | `请上传{字段名}`                     | 请上传活动封面               |
| 超长       | `{字段名}不能超过{N}个字符`          | 活动名称不能超过50个字符     |
| 格式错误   | `{字段名}格式应为{格式}`             | 日期格式应为 YYYY-MM-DD      |
| 超出范围   | `{字段名}须在{最小值}~{最大值}之间`  | 申请金额须在1~99999之间      |
| 唯一性     | `{字段名}已存在`                     | 活动名称已存在               |
| 比较关系   | `{具体业务描述}`                     | 活动开始时间必须早于结束时间 |

## 6. 完整示例

```gherkin
# language: zh-CN
功能: 创建活动
  作为 运营人员，
  我希望 创建一个新的运营活动，
  以便 后续配置活动名单并上架面向用户发放积分奖励。

  # 规则：每个活动的名称必须唯一。（来源：事件风暴 policy）
  # 规则：每个活动的开始时间必须早于结束时间。（来源：事件风暴 policy）
  # 规则：每个活动的结束时间必须晚于当前时间。（来源：事件风暴 policy）

  # 表单字段规格：
  # | 字段名   | 控件类型   | 必填 | 约束                         |
  # | 活动名称 | 文本输入   | 是   | 最大 50 字符；不可重复       |
  # | 活动类型 | 下拉选择   | 是   | 可选值：积分/优惠券/实物     |
  # | 开始时间 | 日期选择器 | 是   | 格式 YYYY-MM-DD              |
  # | 结束时间 | 日期选择器 | 是   | 格式 YYYY-MM-DD；须晚于开始时间；须晚于当前时间 |
  # | 备注     | 多行文本   | 否   | 最大 200 字符                |

  场景: 运营人员成功创建活动
    假设 当前不存在名称为"双十一积分狂欢"的活动
    当 运营人员填写创建活动表单：
      | 字段名   | 值             |
      | 活动名称 | 双十一积分狂欢 |
      | 活动类型 | 积分           |
      | 开始时间 | 2026-11-01     |
      | 结束时间 | 2026-11-11     |
    而且 提交表单
    那么 活动应创建成功
    而且 活动状态应为"待上架"

  场景: 活动名称为空时提交失败
    当 运营人员填写创建活动表单：
      | 字段名   | 值         |
      | 活动名称 |            |
      | 活动类型 | 积分       |
      | 开始时间 | 2026-11-01 |
      | 结束时间 | 2026-11-11 |
    而且 提交表单
    那么 活动名称字段应提示"请输入活动名称"

  场景: 活动类型未选择时提交失败
    当 运营人员填写创建活动表单：
      | 字段名   | 值             |
      | 活动名称 | 双十一积分狂欢 |
      | 活动类型 |                |
      | 开始时间 | 2026-11-01     |
      | 结束时间 | 2026-11-11     |
    而且 提交表单
    那么 活动类型字段应提示"请选择活动类型"

  场景: 活动名称重复时创建失败
    假设 已存在名称为"双十一积分狂欢"的活动
    当 运营人员填写创建活动表单：
      | 字段名   | 值             |
      | 活动名称 | 双十一积分狂欢 |
      | 活动类型 | 积分           |
      | 开始时间 | 2026-12-01     |
      | 结束时间 | 2026-12-12     |
    而且 提交表单
    那么 应提示"活动名称已存在"

  场景: 活动开始时间晚于结束时间时创建失败
    当 运营人员填写创建活动表单：
      | 字段名   | 值           |
      | 活动名称 | 时间异常活动 |
      | 活动类型 | 积分         |
      | 开始时间 | 2026-12-31   |
      | 结束时间 | 2026-12-01   |
    而且 提交表单
    那么 应提示"活动开始时间必须早于结束时间"
```

## 7. 检查清单

写完表单相关场景后，逐项确认：

- [ ] 表单字段规格表已定义，且包含所有字段
- [ ] 每个必填字段都有对应的空值校验场景
- [ ] 有格式/范围约束的字段有对应的非法值场景
- [ ] 跨字段的业务规则有独立场景
- [ ] 唯一性约束有对应的重复值场景
- [ ] 提示语符合统一规范
- [ ] 字段名在规格表、填写步骤、提示语中保持一致
- [ ] 成功场景（happy path）放在最前面
