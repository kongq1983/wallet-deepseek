# 前端 UI 样式规范（管理端与用户端）

> 前端统一设计系统来源：@DESIGN.md。新增或修改前端页面、组件、样式、视觉资产时，必须先读取并遵循该文档。

## 1. 适用范围

- 适用于 `frontend/apps/frontend-admin-web/src/views/` 与 `frontend/apps/frontend-user-web/src/views/` 下页面，以及对应壳层组件与样式文件。

## 2. 设计目标

- 保持管理端与用户端页面视觉风格统一，避免页面间色彩、间距、组件形态漂移。
- 提升前端交付效率，减少重复调样和评审返工。
- 在不改动 shadcn/ui 组件源码前提下，形成可执行、可检查的样式标准。

## 3. 跨端壳层一致性（必须）

- 管理端与用户端工作台必须采用同构的页面骨架：头部区域、左侧菜单区域、主体容器区域的结构一致。
- 头部信息区必须同构：品牌图标、系统名称、用户信息区（头像+名称+次级信息）结构一致。
- 主体容器必须保持一致口径：卡片化主容器、顶部标题区、内容区内边距层级一致。
- 允许差异仅限业务文案、菜单项内容与业务操作组件，不得破坏壳层结构一致性。

## 4. 基础约束（必须）

- `DESIGN.md` 是前端统一设计系统（source of truth）：新增页面与新增样式必须对齐其中的语义与数值口径。
- 样式统一使用 Tailwind 工具类与 shadcn/ui 主题变量；禁止散落硬编码色值（内联 `style` 的任意 hex/rgb）。
- 设计令牌统一使用 shadcn/ui 的 CSS 变量体系（HSL 色彩变量，如 `--background`、`--foreground`、`--primary`、`--border`），通过 Tailwind 语义类（如 `bg-background`、`text-foreground`、`border-border`）消费。
- 禁止新增 `--wl-*`、`--admin-*`、`--uw-*` 等历史或端侧前缀令牌。
- 布局壳层样式统一放在各项目 `src/styles/` 全局维护；组件内仅保留局部差异样式。

## 5. 设计令牌规范

### 5.1 命名规则

- 令牌统一使用 shadcn/ui 标准变量名（`--background`、`--foreground`、`--primary`、`--primary-foreground`、`--muted`、`--muted-foreground`、`--border`、`--input`、`--ring`、`--destructive` 等），定义在 `frontend/packages/ui/` 的全局 CSS 中。
- 暗色模式通过 `.dark` 类切换令牌值，不得为暗色单独维护一套并行类名体系。

### 5.2 色板与语义色

- 必须区分以下语义色：主色（primary）、文本主色与弱文本色（foreground / muted-foreground）、边框色（border）、背景层次色（background / card / muted）、状态色（destructive；成功与警告通过语义类或自定义变量表达）。
- 同一页面内同语义不得重复定义多个近似色值。

### 5.3 字体与字号层级

- 默认中文字体栈建议：`PingFang SC`、`Microsoft YaHei`、`Segoe UI`、`sans-serif`。
- 至少定义三级文本层级：页面标题、区块标题、正文/辅助文本。
- 正文标准字体为 14px（`text-sm`）。

### 5.4 间距与圆角体系

- 优先采用 Tailwind 间距阶梯（4 的倍数，如 `p-2`/`p-3`/`p-4`/`p-6`）。
- 圆角统一使用 shadcn/ui 的 `--radius` 变量与对应语义类（`rounded-md`/`rounded-lg`），避免同页混用过多圆角规格。

## 6. 组件样式规范

### 6.1 卡片与面板

- 卡片/面板必须使用 `Card` 组件，包含可识别的边界（边框、背景层次或阴影至少一种）。
- 同一页面相同语义卡片应复用同一视觉模式（边框、阴影、内边距保持一致）。

### 6.2 表单

- 表单统一使用 shadcn/ui 的 `Form` + `Input`/`Select`/`Checkbox` 等组件。
- 焦点态必须可见（`--ring`），且与主色体系一致。
- 错误态需同时体现颜色与结构反馈（如边框或提示文案），不可仅依赖颜色。

### 6.3 按钮

- 按钮统一使用 shadcn/ui 的 `Button` 及其 `variant`（`default`/`secondary`/`destructive`/`outline`/`ghost`）。
- Hover/Focus/Disabled 状态由组件内置，禁止自行覆盖破坏一致性。
- 主按钮视觉强调必须稳定，不同页面不得随意替换主按钮风格。

## 7. 状态反馈规范

- 每个关键页面应覆盖适用状态：正常态、加载态、错误态（空态按业务需要补充）。
- 加载态与错误态呈现方式需与页面主体风格一致，禁止跳出式风格断层。
- 错误信息需可理解且具可操作性（例如重试、返回或调整输入）。

## 8. 响应式与断点规范

- 管理端与用户端页面必须适配桌面与移动端。
- 断点统一使用 Tailwind 响应式前缀（`sm`/`md`/`lg`）。
- 响应式调整不只改布局，还要保障可读性与可操作性（字号、间距、点击区域）。

## 9. 动效规范

- 动效应服务于信息层级与交互反馈，避免无意义动画堆叠。
- 所有关键交互动效应提供 `prefers-reduced-motion: reduce` 降级处理。
- 动效时长与缓动建议在页面内保持统一，避免“每个组件一套节奏”。

## 10. 图标规范

- 图标统一使用 `lucide-react`（shadcn/ui 默认图标库）。
- 同一页面图标风格必须一致（线性或面性不可混乱穿插）。
- 图标尺寸与文本层级匹配，避免图标喧宾夺主。
- 图标仅作为信息辅助，不得替代必要文字说明。

## 11. 表格与交互统一规范

- 表格统一使用 `Table` 组件（shadcn/ui）或 TanStack Table。
- 表格操作列按钮使用 `Button` 的 `ghost` 变体；删除、撤回等危险动作使用 `destructive` 变体或红色文本。
- 撤回、删除、退出登录必须提供二次确认弹窗（`AlertDialog`）。
- 二次确认弹窗按钮文案统一为 `取消`、`确认`；业务弹窗点击遮罩层不允许关闭。
- 表格空值默认展示 `-`。
- 需要显示单位的字段，单位必须放在列表头并使用括号包裹，如 `申请金额（元）`。
- 纯数字列右对齐；其他列左对齐。
- 表头文本不得换行，且表头字重统一为 `font-medium`/`font-semibold`。
- 表格宽度超出时横向滚动。
- 长文本超过两行时显示省略号，悬停时展示全文（`Tooltip`）。
- 输入框占位文案统一为“请输入”；选择框占位文案统一为“请选择”。
- 金额输入框仅允许输入数字和小数点。
- 列表页必须提供空态组件。

- [ ] 管理端与用户端壳层在头部、侧栏、主体容器结构上保持同构。
- [ ] 主按钮、表单、卡片样式在同页语义一致。
- [ ] 页面未新增 `--wl-*` / `--admin-*` / `--uw-*` 前缀令牌。
- [ ] 已覆盖桌面端与移动端关键布局与可操作性检查。
- [ ] 已覆盖适用状态（正常/加载/错误）并给出评审截图或说明。
